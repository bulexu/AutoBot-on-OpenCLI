# P0 开发计划

交付一个可在 Windows 安装的桌面工作台。开发者用 AI 设计竞品销量同步流程、试跑并导出 `.flow`。接收方在另一台试点机器上导入文件，绑定本机凭证与表，手动重放并查看结果。产品范围以 [PRD](base.md) 为准。

当前已实现 TypeScript 执行原型、`.flow` v1 ZIP 导入导出及通用 OpenCLI 插件。执行原型覆盖有序步骤、HTTP 分页、字段映射、SQLite 按页落盘和 Bitable Upsert 的模拟传输。项目锁定 OpenCLI 2.0.3 为生产依赖。`npm run check` 使用项目内置 OpenCLI 和模拟 HTTP 响应验证插件启动、两页只读预览及跨进程 SQLite 落盘。Windows 随包运行、插件内真实 Bitable 写入和竞品样例仍待联调。

## 里程碑与退出条件

### 当前执行顺序

2026-10 的 X2max 已完成真实写入与回查，验收结果为两条明细、一条汇总，重跑无重复。全量竞品同步和过期数据清理暂缓验证，继续保留在 PRD。

1. **统一运行入口（已实现）。** 通用 OpenCLI 插件执行 HTTP 取数和 Bitable 写入，竞品算子经同一入口运行，测试产品范围作为显式运行参数。HTTP 步骤可引用前序记录，逐条绑定查询参数或请求体字段，并独立分页。亚马逊字段映射、汇率和汇总规则保留在竞品算子。模拟服务覆盖插件预览、写入和重跑。
2. **打通 Windows 桌面链路（开发版已实现）。** Electron 工作台提供文件导入、按流程加密保存样例凭证、指定产品范围、预览、运行和结果查看。开发版执行 `npm run desktop`，从项目依赖解析 OpenCLI。工作台用 Electron 自带的 Node 运行模式启动子进程。已在 macOS 验证窗口加载和受限 IPC，并从打包产物内部执行 OpenCLI 两页预览和 SQLite 落盘。Windows x64 构建机执行 `npm ci` 和 `npm run package:win` 生成 NSIS 安装包。打包保留实际文件路径供 OpenCLI 发现本地插件。Windows 安装、凭证加密和桌面全流程仍需在干净环境实测。
3. **接入 AI 设计（开发版已实现）。** 在「系统设置」保存模型 Base URL、Model 和 AK，配置使用系统加密后保存在本机。工作台先选择 API 或 RPA，再与设计 Agent 对话。API 模式通过对话收集源 cURL、脱敏 JSON 样例和同步目标。Dashboard 管理导入、运行历史、预览和导出。RPA 模式生成待执行验证的操作草案，浏览器执行仍归 P3。当前支持单个 JSON API 经字段映射后批量 Upsert 到飞书。工作台在本机保留请求头凭证，模型只看到接口结构、响应结构和同步目标。LangGraph 编排一次自动修订、OpenCLI 只读试跑和确认导出。导入生成的包后，界面按流程显示源凭证和飞书目标表绑定；Bearer 鉴权字段填写完整头值。已使用模拟模型与源接口验证，真实模型和 Windows 端到端验收待完成。

继续以 `npm run check` 检查格式、lint、类型和测试。桌面代码负责 IPC 和交互，执行逻辑保留在 runtime，外部协议保留在 integrations。

### 原始里程碑与完整范围

| 顺序 | 开发工作 | 退出条件 |
| --- | --- | --- |
| 1. 验证接口和 Windows 运行链路 | 用一个竞品验证卖家精灵 MCP 的实际工具协议、响应封装、目标月份覆盖和分页位置。只读检查四张飞书表的字段及应用权限。在 Windows 用最小安装包验证随附 OpenCLI 启动、标准输入、结构化返回、系统凭证库与 SQLite。 | 保存脱敏接口样例与 Windows 验证记录。明确月份缺失时的取数路径、测试表及实际分页位置。接口调查可与流程包实现同时推进。 |
| 2. 打通手写流程包 | 定稿 v1 的 manifest 与步骤 schema，校验参数、步骤引用、算子和访问声明。实现 ZIP 导入导出、任务绑定、通用 OpenCLI 插件和运行协调。工作台拥有运行状态及保留规则，插件负责执行和按页保存数据。 | 手写包可在 Windows 工作台导入并预览。预览不会调用写入或删除，关闭或异常退出后的运行可识别为中断。每任务保留最近 10 次结果，日志仍可追溯。 |
| 3. 跑通竞品销量样例 | 接入飞书应用鉴权和批量读写。按需要补充 Bitable 读取、逐竞品取数、汇率查找、分组汇总和按月份清理算子。固定绑定汇率表、监控表、明细表和汇总表的角色，按目标表和业务键分别保存 `record_id` 关联。 | 独立测试表验证读取、明细与汇总写入、重复重跑和结果不明后的重跑。确认汇率、分组键和清理边界后才验证删除。明细与汇总成功后执行清理，预览显示拟清理记录。 |
| 4. 接入 AI 设计和确认导出 | 本地解析 cURL、提取凭证并脱敏。LangChain 生成 v1 草稿，LangGraph 编排校验、只读试跑、一次自动修订及开发者确认。 | 给定 cURL、脱敏响应样例和同步目标可生成可执行草稿。资料不足会暂停，接口方法或地址变更会要求确认。只导出通过试跑并经确认的确切版本。 |
| 5. Windows 试点交付 | 完成设计、试跑、导入、参数与凭证绑定、运行进度和结果界面。构建安装包，验证跨机器交付和再次导入新版。 | 在干净 Windows 环境安装工作台，无需手动安装 OpenCLI。开发者设计并导出，接收方用本机绑定完成运行。能查看已确认写入数、失败原因及保留的结果。 |

## 代码结构

先用一个 TypeScript 项目。目录随实际模块落地，现有实现随着功能迁入对应目录。

| 目录 | 职责 |
| --- | --- |
| `src/flow/` | v1 包格式、schema、参数和步骤引用校验、导入导出 |
| `src/runtime/` | 运行协调、顺序执行、预览策略和算子。收敛现有 `execute.ts` |
| `src/integrations/` | HTTP、卖家精灵 MCP、Bitable、OpenCLI 子进程协议和系统凭证库。保留 Bitable 匹配与批次策略，真实传输独立实现 |
| `src/storage/` | SQLite 迁移、任务、运行结果和记录关联。沿用现有 `RunStore` 的职责 |
| `src/design/` | cURL 解析与脱敏、LangChain 模型调用、LangGraph 设计流程 |
| `src/desktop/` | Electron 主进程、preload、renderer 和类型化 IPC |
| `test/` | 执行、适配器契约与端到端样例测试，测试数据使用脱敏 fixtures |

界面通过 IPC 调用应用操作。运行时消费校验后的流程定义和显式传入的依赖。Electron、SQLite 和外部服务的调用留在相应边界，试跑与重放复用算子。凭证通过标准输入注入，日志保留运行 ID、步骤 ID、流程版本和可操作的错误信息。

## 代码风格与交付检查

- TypeScript 启用严格类型。外部 JSON 进入系统时用 `unknown` 接收并校验，AI 草稿与导入文件使用同一套 schema。
- 保持现有 ESM、两空格缩进、单引号和具名导出。统一使用 Prettier 和 ESLint，固定依赖版本并提交锁文件。
- 采用领域命名，如 `flowId`、`taskId`、`runId`、`recordId`。同一职责集中在一处，随着出现真实复用再抽取共用代码。
- 将格式检查、lint、类型检查和测试纳入合并检查。发布前增加 Windows 安装包冒烟验证，重点覆盖 OpenCLI 启动、凭证存取和运行结果读取。
- 日常测试使用可控响应。真实飞书和卖家精灵使用独立联调步骤，执行前核对测试表、凭证权限和目标月份。验收证据记录实际版本、运行结果和脱敏响应。

首批开发从 Windows 运行验证和手写流程包开始。定时任务、在线市场和浏览器操作分别沿用 P1、P2、P3 的安排。
