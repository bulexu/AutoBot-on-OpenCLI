智能自动化 Agent 平台产品详细设计说明书 (PRD)

1. 产品概述

1.1 产品定位

本产品是一个基于 AI 驱动的个人/企业级自动化工作流分发与执行平台。系统以真实浏览器会话（CDP）和三方 API 交互为底座，结合本地 SQLite 存储与飞书协同生态，通过“AI 辅助构建快照、零 Token 极速重放、轻量级智能自愈”的创新机制，打造一个面向开发者的流程设计中心与面向终端用户的免折腾运行环境。

1.2 核心价值

⚬ 设计与运行解耦：开发者通过可视化录制或 AI 自动对齐生成标准化的流程包（.flow），终端用户只需一键导入并配置参数即可运行。
⚬ 零风控与零成本重放：依托本地桌面端架构复用宿主浏览器 Cookie 与登录态，彻底规避无头浏览器的风控拦截；日常重放完全基于本地引擎（0 Token 消耗）。
⚬ 自适应与高可用：通过多重指纹选择器与轻量化 AI 自愈机制，应对第三方系统 UI 改版或接口结构漂移。

1.3 目标用户群体

⚬ 流程开发者（生产者）：RPA 工程师、企业 IT 效率工具开发者、懂基础技术的业务极客。
⚬ 终端业务用户（消费者）：运营人员、销售、HR、财务等需要高频处理重复性跨系统数据搬运的非技术人员。

2. 系统整体架构

P0 采用单一桌面工作台。工作台的本地后端负责流程包校验、凭证绑定、运行日志和 OpenCLI 调用。试跑与正式重放共用执行入口，试跑限制读取页数并生成写入预览。P0 运行期间需保持工作台打开。P1 引入独立的本地执行服务，复用该入口实现定时调度和队列恢复。

桌面工作台使用 Electron + TypeScript。主进程承载本地后端，界面通过受限的 IPC 发起操作并读取进度与结果。流程解析和执行逻辑作为独立的 TypeScript 模块，供 P1 本地执行服务复用。

P0 工作台安装包随附固定版本的 OpenCLI 及其运行环境，试跑和正式重放使用随包版本。Windows 为 P0 首个验收平台，覆盖安装、随包 OpenCLI 启动、系统凭证存取、.flow 导入和手动重放。

P0 的 AI 设计逻辑运行在 Electron 本地后端。LangChain 调用模型生成结构化流程草稿，LangGraph 编排校验、只读试跑、一次自动修订与开发者确认。开发者在本机配置模型凭证。工作台从 cURL 中提取凭证后，只将脱敏请求模板、脱敏响应样例和同步目标发给模型，自动修订仅附带脱敏诊断。真实 API 试跑和飞书写入在本机执行，接收方重放无需模型凭证。

P0 将 API 读取、分页和飞书多维表格批量 Upsert 封装为可复用的内置算子。workflow.json 声明要组合的算子及其输入、输出引用和字段映射。AI 生成声明式配置，由工作台校验。工作台随包交付一个通用 OpenCLI 插件入口，所有流程通过该入口执行内置算子。

业务流程一律由 `.flow` 定义，运行时仅注册可跨场景复用的通用算子。新增场景通过组合现有算子交付，缺少底层能力时按通用输入与输出契约扩展。竞品月销量流程在 `manifest.json` 声明月份、请求间隔和权限，在 `workflow.json` 声明汇率表与监控表读取、站点和 ASIN 展开、接口请求与响应取值、币种换算、汇总分组及两张表的写入规则。目标月份缺数、允许使用父 ASIN 指标的条件，以及缺数时跳过对应汇总组，也由流程定义。

迁移所需的共用能力包括多维表分页读取、记录展开与关联、HTTP 请求参数绑定和节流、JSON-RPC 响应解包、按项记录失败并继续，以及按键分组聚合。运行时提供这些能力及凭证注入、预览、执行记录和按匹配记录 ID 批量写入。竞品包迁移后，从流程校验、执行器、凭证绑定和界面移除 `competitor.monthly` 专用分支。已安装的旧包升级为同 ID 的新版声明式包，迁移时保留可沿用的本机配置。验收覆盖正常取数、部分缺数、请求间隔和重复运行，并检查新增同类流程仅需交付流程包。

P0 按声明顺序串行执行步骤，每步可引用任意前序步骤的输出。分页由算子处理。条件分支与并行执行留待具体场景确认。

HTTP 算子的 `pagination` 可按接口配置 `cursor`、`page` 或 `offset` 策略。请求参数名可自定义，支持查询参数或只读 POST 的请求体字段。响应使用配置的字段路径读取下一游标、是否有下一页或总记录数。页码和偏移量策略也可按不足一页结束。可配置最大页数，超限的正式运行在本步骤停止。已有只声明 `cursorPath` 的流程继续按游标执行。

P0 字段映射支持字段路径取值、常量、缺失值默认值、基础类型转换和键值查找。查找表可以在流程中声明，也可引用前序步骤的输出。试跑展示转换后的字段值。

P0 将分页收集结果按运行写入本地 SQLite，后续字段映射和批量写入可读取该结果。各阶段统一按任务计算保留额度，试跑和正式运行共用同一规则，每个任务默认最多保留最近 10 次运行结果。

工作台在启动 OpenCLI 前创建运行记录，并在子进程退出后更新最终状态、清理超出保留额度的结果。OpenCLI 插件按页将已收集的数据写入该次运行，工作台从 SQLite 读取并展示结果。

P0 工作台同一时间最多执行一次运行，试跑与正式重放共用该限制。运行期间显示进度，并禁用其他运行入口。P1 按任务排队。

分页读取中途失败时，保留已收集的数据并标记为不完整，计入最近 10 次保留额度。本次运行停止在批量写入之前，用户可查看已收集的数据排查问题。手动重跑时重新读取源 API。

密钥保存在系统凭证库，SQLite 只保存凭证引用。工作台经 OpenCLI 子进程的标准输入向通用插件入口传递已校验的流程定义和当前运行所需的凭证。流程包使用凭证占位符，运行日志可记录凭证引用。

P0 由工作台自动校验流程的网络访问声明，执行时核对 HTTP 方法、域名和路径模板，重定向也须重新校验。飞书读写通过内置算子访问绑定的目标表。

3. 核心功能模块设计

3.1 流程录制与生成引擎（开发者端）

提供半自动化的业务动作沉淀工具。

⚬ CDP 浏览器交互录制：
  ⚬ 支持唤起本地 Chrome 进行交互，自动记录用户的点击、输入、滚动等动作。
  ⚬ 自动为每个目标元素提取多级定位指纹（主 CSS、XPath、ARIA Label、相邻文本锚点）。
⚬ 三方 API 智能对齐：
  ⚬ 支持导入 cURL、HAR 抓包文件或 Swagger 文档。
  ⚬ 由 AI 自动解析并生成标准的 API 请求快照，包括动态 Headers、分页游标规则及响应字段的 JSONPath 提取映射。
⚬ 动态参数插槽（Inputs 提取）：
  ⚬ 开发者可将快照中写死的变量（如目标网址、飞书 Table ID、搜索关键字）标记为变量 {{input.keyword}}，这些变量将在用户端作为配置表单展示。

3.2 本地极速重放与智能自愈引擎

保障业务长期稳定运行的核心机制。

⚬ 零 Token 确定性重放：
  ⚬ 定时任务触发后，执行引擎加载 SQLite 中的本地快照，直接下发底层命令（CDP/HTTP），过程无 LLM 参与，实现毫秒级响应。
⚬ 多级容错与回退策略（Fallback）：
  ⚬ 若首选 CSS 选择器失效，引擎自动降级尝试 XPath 或视觉文本锚点定位。
  ⚬ 若 API Token 失效，自动调用快照中预设的 Refresh 链路。
⚬ AI 智能自愈（Self-Healing）：
  ⚬ 当所有静态规则均失效（如前端大改版），挂起当前任务并截取当前 DOM 树与页面截图。
  ⚬ 若用户开启自愈，引擎调用 LLM 传入“失效前特征”与“当前上下文”，由 AI 推荐新定位器并试运行。成功后自动覆盖本地 SQLite 快照。

3.3 流程包分发体系（Workflow Distribution）

实现“流程即应用”的资产化管理。

⚬ .flow 标准流程包规范：
  ⚬ 采用自包含的压缩包格式。
  ⚬ P0 流程包包含 manifest.json（元数据、权限声明、用户配置表单 schema）和 workflow.json（声明式动作节点与逻辑流）。
  ⚬ manifest.json 的 schemaVersion 标识流程包格式，version 标识流程发布版本。P0 支持 schemaVersion 为 1 的流程包，导入更高格式版本时提示升级工作台。
  ⚬ 工作台将已校验的流程定义交给随包交付的通用 OpenCLI 插件执行，并接收结构化结果。
⚬ 安全沙箱与权限管控：
  ⚬ P0 导入流程包时，工作台自动校验权限声明和流程定义，无需用户确认网络权限。
  ⚬ 运行时严格限制网络访问范围，禁止越权请求。

⚬ Web 流程市场：
  ⚬ 首版面向企业内部用户。
  ⚬ 市场接入飞书单点登录和飞书一键注册。Web 服务通过飞书应用鉴权验证用户身份。首次鉴权成功时，账号注册 API 根据飞书身份创建市场账号，新账号默认获得使用者权限。后续登录沿用该账号。
  ⚬ 市场管理界面提供账号管理，管理员可查看账号、管理角色和启停账号。
  ⚬ 账号停用后立即终止市场访问，包括已有会话中的浏览、安装和获取更新。工作台保留已安装版本，可继续本地执行。工作台获知账号停用后，停止以该账号同步版本状态和上报运行数据。
  ⚬ 发布者账号停用后，已上架版本继续可用。管理员可手动将流程维护权移交给同企业的其他发布者，接手者提交的新版仍须审核通过后上架。
  ⚬ 移交维护权时沿用原市场条目和流程 ID。市场显示当前维护者，各版本保留原提交者。已有安装继续接收该条目的更新，使用统计连续累计。
  ⚬ 维护权移交后，新维护者可撤回尚未审核的提交，再重新提交审核。
  ⚬ 未上架的版本撤回待审提交后可沿用原版本号重新提交，每次提交保留独立的审核记录。已上架版本的内容固定，后续修改须使用新版本号提交审核。
  ⚬ 市场提供管理界面，管理员定期集中审核开发者提交的流程版本，并查看权限声明和版本差异。首发和更新均须审核通过后上架。新版审核期间，已上架版本继续可用；新版上架后，工作台才提示更新。
  ⚬ 管理员可下架或撤回流程版本。下架后停止新安装和更新，已安装版本可继续执行。撤回后停止分发，已安装该版本的工作台在下一次成功连接市场后阻止该版本继续执行，并向用户显示撤回原因。
  ⚬ 对仍具备市场访问权限的账号，工作台在启动时和每次运行市场安装的流程版本前尝试检查撤回状态。市场暂时不可达时，沿用本机最近一次成功检查的结果，并记录检查失败。
  ⚬ 新版由用户按任务确认后切换。同一个已安装流程下的不同任务可以使用不同版本，工作台显示每个任务当前使用的版本。切换前复用 P1 的必填参数和目标表兼容性检查。检查失败时，提示需要调整的配置，该任务继续使用当前仍可执行的版本。
  ⚬ 用户可将通过文件安装的流程手动关联到市场条目。工作台核对流程 ID 与发布者归属，用户确认关联后可接收市场更新并沿用兼容的本机配置。版本切换前仍须通过兼容性检查。
  ⚬ 排队的运行在实际启动时选用任务当时启用的流程版本，并沿用至本次运行结束。更新通过检查后，新版从下一次实际启动的运行起生效，包括已入队的运行。运行日志记录实际执行的版本。
  ⚬ 工作台保留各任务正在使用的版本及其上一版本，用户可按任务手动回退。回退前确认该版本仍可执行，并重新检查当前必填参数和目标表兼容性。回退从该任务的下一次运行起生效，已写入的数据由用户按业务情况处理。
  ⚬ 开发者发布流程包及其版本，接收方在市场发现流程，通过本地工作台安装并获取版本更新。
  ⚬ 市场汇总流程下载、安装、升级和运行情况，供发布者了解各版本的使用情况。本地工作台执行流程并上报运行结果，凭证和业务数据保存在本机。
  ⚬ 使用实例按工作台安装 ID 与流程 ID 的组合去重，升级沿用同一实例。市场分别展示累计安装实例数、最近 30 天至少运行一次的活跃实例数和运行次数。
  ⚬ 发布者可查看自己发布的流程按版本汇总的统计。管理员可按安装实例查看运行记录，包括实际执行版本、运行时间、结果和耗时。具体报错和业务数据保留在本地工作台。
  ⚬ 市场不可达时，工作台将待上报事件保存在本机，恢复连接后自动补报。市场按事件 ID 去重，并按事件实际发生时间统计。

3.4 飞书生态深度集成

将自动化能力无缝嵌入日常办公协同平台。

⚬ 多维表格（Bitable）数据泵：
  ⚬ 内置飞书 Bitable 数据同步算子，支持批量读取和批量 Upsert。以 Bitable 接口返回的 record_id 关联目标记录，更新时使用该 record_id。
  ⚬ 目标表需有一列保存源记录标识。新增时同时写入该标识并在本机保存接口返回的 record_id。本机缺少关联时，先按源记录标识查找目标记录，找到后恢复关联，确认无匹配后再新增。
⚬ 飞书机器人卡片交互：
  ⚬ 自动化任务运行结果（成功统计、异常自愈警告、需人工介入验证码）自动推送到飞书群或单聊。
  ⚬ 支持卡片内直接点击按钮触发动作（如“批准同步”、“重试任务”）。

3.5 AI 对话与 CLI 调度控制台

为终端用户提供直观的操作入口。

⚬ 自然语言意图驱动：
  ⚬ 客户端内置对话框，用户可通过语言触发本地指令（例：“帮我把 CRM 同步任务改为每天早上 9 点运行”）。
⚬ 统一的 CLI 接口：
  ⚬ 所有的 UI 动作底层均映射为标准 CLI 命令（如 bot flow run xxx），便于高级用户集成到自有的 Shell 脚本或 CI/CD 流程中。

4.2 本地 SQLite 核心表结构

系统运行时依赖的核心本地库表结构：

表名	核心字段	说明
installed_flows	flow_id, version, manifest_json, status	记录本地已安装的自动化流程包资产。
flow_tasks	task_id, flow_id, version	记录已安装流程的任务，P0 每个流程使用一个任务，P1 支持多个任务，P2 按任务选择运行版本。
flow_configs	flow_id, task_id, config_key, config_value, is_secret	按任务存储本机配置参数；凭证类配置仅存储系统凭证库引用。
cron_jobs	job_id, task_id, cron_expr, next_run_time, enabled	记录任务的定时调度配置（P1）。
execution_logs	log_id, flow_id, task_id, version, start_time, end_time, status, error_trace	按任务记录实际执行版本和详细日志。
snapshots_repo	snapshot_id, flow_id, type (CDP/API), data_json	具体的业务执行节点快照库，自愈机制会动态更新 data_json。

5. 演进路线图

⚬ P0 API 流程闭环
  完成 API 场景的流程设计、分发和重放，接通飞书多维表格的批量读取与批量写入。
  工作台接入 AI，根据开发者提供的接口资料与同步目标生成声明式流程定义。试跑与本地重放共用随包交付的 OpenCLI 插件入口。
  P0 设计入口接收一条 cURL、一份脱敏响应样例和同步目标。样例缺少设计所需的分页信息时，提示开发者补充。
  导出前须在工作台试跑并由开发者确认结果。试跑读取有限页真实 API 数据，展示分页结果、字段映射和拟写入记录，预览期间不写入飞书。P0 验收使用至少两页源数据验证游标推进，并在独立测试表验证批量写入。
  试跑失败时，AI 可根据诊断自动修订草稿一次，并在相同的只读条件下复跑。复跑仍失败或接口资料不足时，暂停并请开发者补充信息。仅导出通过试跑且经开发者确认的草稿版本。
  只读试跑支持 GET 查询和开发者明确标记为只读的 POST 查询。自动修订可调整游标路径、分页参数和字段映射。请求方法或接口地址发生变化时，须由开发者确认后再试跑。
  源 API 支持本机配置的 API Key 和 Bearer Token。流程包及模型上下文使用凭证占位符，工作台在试跑和重放时注入本机凭证。源 API 返回 401 时，提示用户检查或更新凭证。OAuth 授权与令牌自动刷新列为后续待确认能力。
  飞书多维表格通过本机配置的飞书应用身份读写。开发者绑定有权访问测试表的应用身份来验证写入，接收方导入后绑定有权访问其目标表的应用身份和目标表。
  开发者导出 .flow 文件并交付给接收方。流程包携带流程定义和参数声明。接收方在工作台导入文件，绑定本机凭证与目标表，手动运行并查看结果。工作台调用 OpenCLI 执行。文件分发场景下，新版通过再次导入交付。
  P0 每个已安装流程使用一个手动任务，运行结果归入该任务。P1 扩展为同一流程可创建多个独立任务。
  批量 Upsert 验收覆盖首次新增和再次重放。对已关联的源记录，再次重放时使用 Bitable 返回的 record_id 更新同一条目标记录。
  批次写入结果不明时，停止本次运行并展示已确认写入的记录数。用户可手动重跑整个流程。重跑时，已有 record_id 的记录按关联更新，缺少关联的记录先按源记录标识查表，确认无匹配后再新增。验收须模拟批次中断，并检查重跑后的目标记录数和内容。
  部署与验收约定：同一批源数据同步到同一张目标表时，由一台机器负责执行。迁移前停止旧机器上的执行。
  每张目标表只接收同一个源记录标识范围的数据。例如，两个可能使用相同 lead_id 的 CRM 实例分别绑定各自的目标表。
⚬ P1 执行前检查与定时任务
  检查流程的必填参数，以及目标多维表格的数据表是否可用、所需字段是否存在、字段类型与格式是否符合流程要求。支持定时任务。
  保存任务配置时和每次运行启动时执行上述检查。运行前检查失败时，在第一批写入前结束本次运行，显示不可用的目标表、缺失参数或不兼容字段等具体原因。后续触发照常检查。
  同一个已安装流程可以创建多个独立任务。每个任务有独立的参数、凭证绑定、目标表、时间表和执行队列。任务创建后固定目标表，使用其他目标表时创建独立任务。同一目标表只分配给一个同步任务。
  本机执行服务恢复后，每个定时任务只补跑最近一次错过的触发，记录执行结果，随后按原时间表继续调度。
  同一个任务的手动触发与定时触发共用队列，按入队顺序串行执行。任务仍在运行时，新触发进入队列，工作台显示排队状态。
  执行服务重启后，恢复已入队的运行并保持原顺序。重启前正在执行的运行标记为中断，由用户决定是否手动重跑。离线期间最近一次错过的定时触发排在恢复的运行之后。
⚬ P2 企业内部流程市场
  提供飞书单点登录、一键注册、账号注册 API、账号管理、流程版本提交、管理员审核、上架、发现、安装、在线更新、手动版本回退和使用统计。P0 试点使用 .flow 文件交付。
  原规划中的运行时 AI 自愈与客户端对话控制台，交付阶段待确认。
⚬ P3 浏览器操作流程
  接入 opencli，支持浏览器操作场景的流程执行。

6. P0 端到端验收样例

指定月份的竞品销量同步使用同一个飞书多维表格中的四张表：

1. 从[站点汇率表](https://aimagene.feishu.cn/base/ViXsbD4aLa3ja5ss0jtcyPedngh?table=tbl4IFfAMtykDmb2&view=vew6qUQlp2)读取各站点汇率。
2. 从[竞品监控表](https://aimagene.feishu.cn/base/ViXsbD4aLa3ja5ss0jtcyPedngh?table=tbl1gGQJZpUsUPE8&view=vew3uB5Go3)读取监控竞品。
3. 对各竞品调用卖家精灵 MCP 接口 `POST https://mcp.sellersprite.com/mcp`，通过 JSON-RPC `tools/call` 调用 `asin_sales_trend`，按站点和 ASIN 获取指定月份的销售数据，并处理分页。请求使用本机绑定的 `secret-key`。样例入参为 `marketplace=US`、`asin=B0DDXCM29Z`。
4. 将销售明细写入[销售明细表](https://aimagene.feishu.cn/base/ViXsbD4aLa3ja5ss0jtcyPedngh?table=tbl3CgYf4xmw1ZTb&view=vewbEADOtk)。
5. 将汇总结果写入[销售汇总表](https://aimagene.feishu.cn/base/ViXsbD4aLa3ja5ss0jtcyPedngh?table=tblP2rZ9sKG82cHr&view=vew4qBMI95)。
6. 清理销售明细表中三个月前的数据。

该样例覆盖多表读取、逐竞品取数与分页、明细和汇总分别写入，以及按时间清理明细。月份参数与分页协议、字段映射、汇率与汇总口径、记录关联规则及清理时间边界在实现时根据接口和表结构确认。只读试跑展示拟写入和拟清理结果。
